# Pull Request作業手順

ユーザーがGitHub Pull Requestの作成、編集、更新、準備を依頼したときに使用する。

## GitHubを変更する前に

1. 現在のブランチ、upstream、ベースブランチ、コミット、作業ツリーを確認し、比較範囲を確定する。
2. 利用環境で適用される指示ファイル、Pull Requestテンプレート、コントリビューション手順などのリポジトリ指示を読む。
3. ブランチに意図した変更だけが含まれ、必要なテスト・チェックが実行済みであることを確認する。
4. PR作成、ブランチpush、レビュアー変更、リモートPR編集は外部状態の変更である。ユーザーがその操作を明確に許可したときだけ実行し、それ以外はタイトル・本文を準備して変更直前に確認する。

## PR本文

- ユーザーに見える結果または技術的な成果を表す簡潔なタイトルにする。
- 何をなぜ変更したかを要約する。
- 影響範囲、マイグレーション、ドキュメント更新、既知の制限を記載する。
- 実行した検証コマンドと結果を正確に列挙する。
- 無関係な既存変更は、PRに含めず必要に応じて注記する。
- コミット追加後のPR更新では、既存本文を確認して今回のコミットの目的・影響範囲・検証結果だけを追記または修正する。累積した変更と矛盾する古い記述を残さない。

利用環境で使用できるGitHub CLI、認証済みAPI、またはブラウザ操作機能を使用する。必要な操作手段や権限がない場合は、準備した内容と未実行の操作を報告する。既存PRを更新するときは有用な文脈を保持し、依頼された部分だけを変更する。PR説明の更新前には、変更案をユーザーへ提示して明示的な確認を得る。明示的な指示なしにforce-push、PRのclose、再オープンを行わない。

PRのURL・番号、最終タイトル、変更した本文の範囲、未完了のチェックを報告する。
