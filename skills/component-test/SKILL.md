# Component Test

単一のUIコンポーネントまたは関連する小さな部品群を、実際のレンダリング環境でマウントして検証する。画面全体・ブラウザ全体・実サービスは起動せず、ユーザーが見て操作できる契約を中心に扱う。

## 利用すべき場面

- ボタン、フォーム、入力欄、ダイアログ、テーブル、カード、ナビゲーション部品を検証するとき。
- ローディング、成功、空、エラーなどの表示状態を検証するとき。
- コンポーネント間のイベント連携、props、入力、コールバック、アクセシビリティを検証するとき。
- 必要な依存だけをモック化して、単一部品を高速に検証するとき。

## 利用すべきでない場面

- UIを持たない関数、Model、Serviceのロジックは `unit-test`。
- アプリ起動、複数画面、実DB/APIをまたぐユーザーフローは `integration-test`。
- 基準画像とのレイアウト・色・余白の差分は `visual-regression-test`。

## 実装ワークフロー

1. 言語、UIフレームワーク、テストランナー、UIテストライブラリを調査する。既存テストの配置・命名規則、モックライブラリ、CI実行方法、アクセシビリティ検証方法を確認する。
2. 対象コンポーネントの責務、props、入力、イベント、表示状態、アクセシビリティ要件、既存テストを明確化し、重複を除外する。
3. Arrange / Act / Assert（または Given / When / Then）で、主要なユーザー操作と期待結果を設計する。loading、success、empty、error、入力境界、無効操作を対象に含める。
4. 対象コンポーネントだけをマウントし、外部API・認証・時刻・乱数などは既存方針のMock、Stub、Fake、Fixtureで固定する。実ネットワーク、実DB、実ブラウザ全体、共有DOMや共有状態は使わない。
5. ユーザー視点でロール、ラベル、表示テキスト、入力欄、ボタン、キーボード操作、フォーカス、イベント結果を検証する。CSSクラス、内部状態、子要素の構造など変更されやすい実装詳細に過度に依存しない。
6. セレクタや画面操作が複数テストで必要なら Page Object Model または Component Object Model を使う。Objectには要素の取得と操作だけを置き、Testにはユーザーシナリオと期待結果、Mock/Fixtureにはテストデータと外部依存を置く。
7. 固定sleepではなく、表示、イベント、リクエスト完了、状態変化など意味のある条件を待つ仕組みを使う。各テストが自分でDOMと状態を初期化し、任意順・単独実行で安定するようにする。
8. 対象テストを実行し、失敗を実装・テスト・環境の問題に分類して修正する。製品コードの変更はテスト成立に必要な最小限にする。
9. 対象・関連テスト、可能ならFormat、Lint/Analyze、全テストを実行し、保守性、可読性、実行速度、セレクタの再利用性を確認する。

## POM / Component Objectの分離

- Page/Component Object: 要素の取得、セレクタ、ユーザー操作、状態取得だけを定義する。
- Test: Given / When / Then または Arrange / Act / Assertによるユーザーシナリオと期待結果を記述する。
- Mock/Fixture: テストデータ、外部API、認証、時刻などの依存と初期状態を提供する。
- Objectへ業務ルールやアサーションを置かず、Test本体へセレクタや低レベル操作を分散させない。

## 完了条件

- 主要なユーザー操作と期待結果が検証されている。
- loading、success、empty、errorなど該当する各表示状態が検証されている。
- props、入力、イベント、アクセシビリティ、必要なキーボード操作・フォーカスが検証されている。
- セレクタと操作が再利用可能なObject構造に整理されている。
- テスト間でDOMや状態を共有せず、実行順序に依存しない。
- CSSクラスなどの変更されやすい実装詳細に過度に結びついていない。

## 検証方法

- 対象テストを絞って実行し、単独実行と関連テスト実行の両方を確認する。
- 固定sleepがなく、状態・イベント・表示条件を待っていることを確認する。
- 可能ならCIと同じヘッドレス設定で複数回実行し、非同期処理とフォーカス操作の安定性を確認する。
- 標準のFormat、Lint/Analyze、全テストも実行する。
- 実行できない場合は、テストランナー、ブラウザ/エミュレーター、フォント、追加設定、未検証範囲を具体的に報告する。
