# Visual Regression Test

主要画面や重要UIコンポーネントを、固定した描画条件でスクリーンショット化し、基準画像と比較する。ピクセル差分を無条件に受け入れず、差分の意味を確認して意図しないUI回帰を検出する。

## 利用すべき場面

- 主要画面、重要UIコンポーネント、レスポンシブレイアウトを保護するとき。
- ライト/ダークテーマ、ローディング・空・エラー状態、多言語表示を比較するとき。
- 主要ブラウザ、画面サイズ、OS・レンダリング環境ごとの見た目を管理できるとき。

## 利用すべきでない場面

- API、計算、バリデーション、保存結果は `unit-test`。
- クリック、入力、状態遷移、イベント連携の機能確認は `component-test` または `integration-test`。
- 基準画像、決定的な実行環境、差分レビューを維持できない場合は無理に追加しない。

## 実装ワークフロー

1. 言語、UIフレームワーク、画像比較/Goldenランナー、スクリーンショット取得方法、基準画像の保存場所、更新コマンド、CI設定を調査する。既存の命名、許容差、成果物、レビュー手順を尊重する。
2. 対象ごとに、次の描画契約を定義する。曖昧なまま基準画像を作成しない。
   - ビューポートサイズとPixel ratio
   - ブラウザまたはレンダリング環境、OS、対象バージョン
   - テーマ（ライト/ダークなど）
   - 言語、ロケール、タイムゾーン
   - 固定するテストデータと状態
   - アニメーション、トランジション、動画の扱い
   - 画像比較方式とプロジェクトに適した閾値
   - 基準画像、実行時画像、差分画像の保存場所
   - 基準画像を更新してよい条件とレビュー担当
3. 対象画面・コンポーネントと状態（正常、ローディング、空、エラー、長文、境界レイアウトなど）を明確化し、既存の画像テストと重複しない最小の高価値ケースを選ぶ。
4. スクリーンショット取得前に状態を決定的にする。日付、時刻、乱数、環境変数、広告、外部画像、API応答、フォント、ユーザー状態を固定またはモック化し、アニメーション・遅延・カーソルなどを無効化または完了条件まで待つ。
5. POMまたはComponent Objectを使う場合、Objectには画面操作と要素取得だけを置き、スクリーンショット取得処理を分離する。Testには表示状態と撮影条件、Fixtureにはテストデータと依存を置く。
6. 指定したブラウザ、画面サイズ、テーマ、言語、フォントで画像を取得し、基準画像・実行時画像・差分画像を同じ識別子で比較可能な成果物として保存する。
7. 差分が出たら、差分の位置・範囲・意味を確認し、意図した変更、環境差、テスト不安定性、意図しない回帰に分類する。単なるピクセル差分の大きさだけで判断しない。
8. 意図した変更であること、描画契約が正しいこと、関連機能テストが成功していることを確認した場合だけ基準画像を更新する。スナップショットを無条件に更新したり、回帰を隠すために閾値を緩めたりしない。
9. 対象画像テスト、関連テスト、可能ならFormat、Lint/Analyze、全テストをCIと同じ条件で実行し、再実行して安定することを確認する。

## 決定的な描画条件

- フォントを固定し、CIへ同じフォントとフォント読み込み手順を用意する。
- 画面サイズ、Pixel ratio、ブラウザ、OSまたはレンダリングエンジンを固定し、差異が避けられない場合は対象セットごとに基準画像を分ける。
- 日付、時刻、乱数、タイムゾーン、ロケール、ネットワーク応答、外部画像、広告、ユーザー識別情報をfixtureまたはモックで固定する。
- アニメーション、トランジション、動画、点滅、キャレットを無効化するか、明確な安定状態を待って撮影する。固定sleepだけで安定を作らない。
- 閾値は既存プロジェクトの標準と描画ノイズの実測に基づき、変更理由を記録する。意味のあるUI差分を通すほど広い許容値にしない。

## 完了条件

- 主要画面または重要コンポーネントの基準画像が、対象ごとの描画契約とともに管理されている。
- 同じ条件で実行すると同じ結果になり、CIで再現可能である。
- 意図しないUI変更を、差分画像と意味の確認によって検出できる。
- 基準画像、実行時画像、差分画像を比較可能な形で保存できる。
- 差分確認、意図した変更の承認、基準画像更新の手順が明確でレビュー可能である。
- 操作と撮影処理、テストシナリオ、Fixtureの責務が分離されている。

## 検証方法

- 対象の画像テストを実行し、基準画像・実行時画像・差分画像・ログを確認する。
- 差分を目視または適切な差分ビューアで確認し、閾値内でも意味のある変更がないか確認する。
- 同一条件で複数回、可能ならCIと同じOS・ブラウザ・フォント・画面サイズで実行して安定性を確認する。
- 基準画像更新時は、変更理由、対象、描画条件、差分確認結果、関連テスト結果をレビュー記録に残す。
- 実行できない場合は、画像比較ランナー、ブラウザ/端末、フォント、基準画像生成、CI設定などの不足と未検証範囲を具体的に報告する。
