# コードレビュー作業手順

ユーザーがコードレビューを依頼したとき、またはコミット、ブランチ、Pull Requestの指摘事項を求めたときに使用する。

## 手順

1. 比較対象のベースを確定し、完全な差分、変更ファイル、周辺コード、テスト、設定、利用環境で適用されるリポジトリ指示ファイルのルールを確認する。
2. 実装を判断する前に意図した挙動を理解する。必要に応じて、変更された入力が状態管理、永続化、UI、エラーパスをどう通るか追跡する。
3. スタイルの好みより具体的な不具合を優先する。正確性、リグレッション、データ損失、セキュリティ・プライバシー、並行性、エラー処理、性能、互換性、テスト、必要なドキュメント更新を確認する。
4. 指摘をコードで裏付け、必要に応じて対象を絞ったテスト、静的解析、最小再現を実行する。実行していないチェックを実行済みと報告しない。
5. 指摘を重大度順に先に報告する。
   - **Critical**: セキュリティ問題、データ損失、リリースを阻害する失敗
   - **High**: 起こりやすい機能リグレッション、主要導線の破損
   - **Medium**: 重要な正確性、保守性、カバレッジの不足
   - **Low**: リスクが限定的な問題、推奨される改善
6. 各指摘にはファイルと行、具体的な問題、影響、絞り込んだ修正方針を含める。指摘がない場合はその旨と、残るテスト上の制限を記載する。

レビューコメントは分析であり、コード変更やリモート投稿の許可ではない。ユーザーが別途依頼しない限り、ファイル編集、approve、merge、レビューコメント投稿を行わない。
