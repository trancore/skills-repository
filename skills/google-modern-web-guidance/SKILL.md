# Modern Web Guidanceの読み込みと適用

依頼に関連するガイドだけを都度取得し、対象プロジェクトの実装判断に使う。このスキルは公式CLIを利用する独自の日本語スキルであり、公式スキルやガイド本文、CLI本体は同梱しない。

## 発動条件と作業範囲

- Web UI、CSSのレイアウト・アニメーション、ブラウザAPIなどの実装、改善、レビューで使用する。フレームワークを使う場合も、その中のHTML・CSS・ブラウザ側JavaScriptに関する判断を対象とする。
- ガイドの検索・取得、既存実装との照合、依頼範囲内での実装またはレビューを行う。レビューのみの依頼ではコードを編集しない。
- 全ガイドの一括読み込み、`legacy-scan` によるリポジトリ全体の調査、Chrome拡張専用の手順は含めない。他のスキルの存在や実行を前提にしない。

## 実行環境

- Node.js 22以上、npx、コマンド実行機能とネットワーク接続を前提とする。実行時に利用できるバージョン・機能と権限を確認し、利用環境の制限に従う。Windowsで必要な場合は `npx.cmd` を使う。
- `npx -y modern-web-guidance@latest` で公式CLIを取得・実行する。公式スキルのインストール、プロジェクトの依存関係への追加、設定ファイルの変更は通常手順に含めない。
- CLIは検索語などの匿名利用情報を収集する。検索語には一般的なWeb機能・UIの名称を使い、秘密情報やプロジェクト固有の情報を含めない。無効化が必要な環境では、公式に用意された環境変数 `DISABLE_TELEMETRY=1` を利用する。

## 読み込みと適用の手順

1. **対象と制約を確認する。** 依頼、適用されるプロジェクト指示、既存実装・関連テストから、対象のUIや機能、フレームワーク、対応ブラウザの方針を把握する。実装とレビューのどちらを求められているか確認する。
2. **関連ガイドを検索する。** 作業対象のプロジェクトを作業ディレクトリとし、次のコマンドを実行する。検索語は1つのWeb機能やUIパターンに絞った、動作を表す短い英語句を目安にする。フレームワーク名やファイル名を並べず、複数の機能は分けて検索する。

   ```sh
   npx -y modern-web-guidance@latest search "<query>"
   ```

   例えば、ダイアログを外側のクリックで閉じる依頼なら `"light dismiss dialog"` とする。結果の `description` を読んで関連する `id` を選び、関連度の順位だけで採用しない。空の結果や無関係な結果しかなければ、具体的なUI名や同義語で一度だけ検索し直す。それでも一致しなければ、該当ガイドを確認できなかったと報告し、無関係なガイドで補わない。
3. **選んだ本文を取得する。** 検索結果で確認できたIDを使い、次のコマンドを実行する。必要な場合だけ、検索結果にある関連分野のガイドも取得する。

   ```sh
   npx -y modern-web-guidance@latest retrieve "<id>"
   ```

   `id` やガイド内容を推測で作らない。出力が大きく、一時ファイルへの保存が案内された場合は、そのファイルを読み取り機能で最後まで確認する。表示が途中で切れていれば、未読の範囲も分割して読み、互換性やフォールバックの指示を読み落とさない。
4. **適用方法を判断する。** 取得したガイドの推奨事項、注意点、互換性情報を対象コードと照合する。下記の対応ブラウザの扱いに従い、フレームワークのライフサイクル、SSR、既存部品・規約に合わせる。ガイドの適用を理由に、依頼にない機能追加、ライブラリ置換、設定変更へ範囲を広げない。
5. **依頼された作業へ反映する。** 実装では必要な変更を行い、取得したガイドの該当事項に沿っているか確認する。レビューでは具体的なコードとガイドの根拠を結び付け、挙動・互換性への影響がある指摘と任意の改善案を区別する。
6. **確認して報告する。** 実装した場合は、対象プロジェクトで確認できる既存の検証手段から変更に必要なものを選ぶ。実行結果と未実施の確認を区別し、参照したガイドと判断へ反映した点を短く報告する。ガイドとの照合だけで、実行時の挙動を検証済みとしない。

## 対応ブラウザと取得失敗の扱い

- ユーザーやプロジェクトに対応ブラウザ・Baselineの指定があれば、それを優先し、ガイドの互換性情報と照合する。指定がなければ、公式の既定値である **Baseline Widely available** を基準にする。それ以外の機能では、ガイドにある機能検出、段階的な拡張、フォールバックの要否を確認する。
- ガイドとプロジェクト要件が両立しない場合は、衝突と影響を示す。プロジェクトの対応ブラウザを勝手に変更したり、必要なフォールバックを省いたりしない。
- CLIが利用できない、ネットワークに接続できない、権限がない、本文の取得に失敗した場合は、失敗した段階と理由を報告する。取得できたガイドだけで進められる範囲と、未確認の範囲を分ける。未読の本文を記憶で補って適用済みと扱わない。
- 必要な根拠が得られない部分は未確認とし、独立して進められる依頼範囲の作業を続ける。環境設定の変更や再試行を無制限に繰り返さない。

## 出力

通常の実装・レビュー結果に、次の情報を簡潔に添える。固定の見出しや長い引用は必須にしない。

- **参照ガイド**：実際に取得したIDと参照先。CLIが示すURLを使い、個別URLを確認できなければ、IDと公式のガイド一覧を示す。
- **反映した判断**：採用したパターン、必要なフォールバック、レビューの根拠など。適用しなかった事項は、判断に関係する場合だけ理由を示す。
- **確認結果・未確認事項**：実施した検証と結果、検索で一致しなかった対象、本文を取得できなかった理由など。取得・参照だけで変更や動作確認を実施済みとしない。
